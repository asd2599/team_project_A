# Product Requirements Document (PRD) - AI 다마고치 v1.1

## 1. 프로젝트 개요 (Overview)

본 프로젝트는 사용자의 텍스트, 음성, 행동 데이터를 실시간으로 분석하여 **AI 다마고치의 감정 상태**를 도출하고, 이에 맞는 시각적·청각적·텍스트 피드백을 제공하는 시스템 시스템이다. 기존의 단순 파라미터 기반 육성을 넘어 사용자의 대화 요령(공감, 논리, 설득)을 실시간으로 분석하고 코칭하며, 위기 감지 시 사회적 안전망과 연동하는 디지털 멘탈케어 동반자 플랫폼을 목표로 한다.

## 2. 타겟 유저 (Target Audience)

- **Primary**: 대면 소통에 피로감을 느끼지만, 정서적 유대감이 필요한 2030 세대 1인 가구.
- **Secondary**: 자신의 커뮤니케이션 스킬(화법)을 객관적으로 분석받고 개선하고 싶은 사용자.

## 3. 핵심 기능 상세 명세 (Detailed Functional Requirements)

### 3.1. 다중 입력 인터페이스 (STT/TTS & Text)

- **기능**: 사용자는 텍스트 타이핑 뿐만 아니라 마이크 버튼을 통해 음성으로 다마고치와 소통할 수 있다.
- **세부 요구사항**:
  - 브라우저 내장 Web Speech API 또는 MediaRecorder를 사용하여 음성 녹음.
  - 녹음된 음성(.webm, .wav)을 처리하여 STT 모듈(Whisper 등)을 통해 텍스트로 변환.
  - 응답 시 다마고치의 성격과 현재 감정 상태(기쁨, 분노 등)에 맞는 억양/톤을 적용한 TTS 반환.

### 3.2. AI 감정 및 대화 분석 엔진 (LLM + Classification)

- **기능**: KoBERT/GPT를 활용하여 사용자의 문장에서 [공감, 논리, 매력] 점수와 기본 감정 요소를 추출.
- **세부 요구사항**:
  - 사용자의 발화 텍스트 당 1~10점 척도의 [공감, 논리, 매력] 점수를 JSON 형태로 반환 (Function Calling 적용).
  - 에크만의 6기본 감정(기쁨, 슬픔, 분노, 놀람, 혐오, 공포) 중 텍스트에 내포된 가장 높은 확률의 감정을 도출.

### 3.3. 진화 및 동적 능력치 시스템 (Dynamic Evolution System)

- **기능**: 대화 점수에 따라 다마고치의 스탯이 쌓이며, 특정 임계점 돌파 시 외형 및 페르소나 변경.
- **세부 요구사항**:
  - `empathy`, `logic`, `charm` 각각의 경험치가 쌓여 100을 넘을 때마다 해당 성향 기반의 레벨업 발생.
  - 예: 논리(logic)가 가장 높은 상태로 레벨 3 도달 시 -> '안경 쓴 학자 다마고치'로 외형 변경.
  - 진화에 따라 다마고치의 기본 말투(Prompt Persona)가 변경됨(예: 공감형 -> 따뜻한 말투, 논리형 -> 분석적/조언형 말투).

### 3.4. AI 코칭 리포트 대시보드

- **기능**: 주간/월간 단위로 자신의 커뮤니케이션 스킬을 파악할 수 있는 시각화 데이터 제공.
- **세부 요구사항**:
  - React + Chart.js(Radar Chart)를 활용하여 스킬 분포도 시각화.
  - 사용자가 가장 많이 사용한 긍정/부정 단어를 워드 클라우드로 제공.

### 3.5. 위기 감지 및 안전망 시스템 (SOS Trigger)

- **기능**: 사용자의 누적 감정 상태가 임계치를 넘을 경우 개입.
- **세부 요구사항**:
  - 최근 3일간 부정 발화 비율이 80% 이상이거나, 특정 Trigger Words("우울해", "죽고싶어" 등) 감지 시 발동.
  - 다마고치가 우려하는 모션과 함께 전문 상담 번호(1393) 및 상담 센터 링크를 다이얼로그 모달로 강제 팝업.

## 4. 데이터베이스 구조 (High-Level Data Model)

1. **Users**: 로그인 정보 (OAuth 지원), `id`, `provider`, `nickname`
2. **Damagotchis**: 캐릭터 정보, `name`, `level`, `hunger`, `happiness`, `empathy_exp`, `logic_exp`, `charm_exp`, `status`
3. **Logs/Memories**: 사용자 발화 기록, AI 응답, `action_type`, `sentiment_score`, `raw_text`

## 5. 비기능 및 시스템 요구사항 (Non-Functional Requirements)

- **응답 속도**: STT -> LLM -> TTS까지의 전체 사이클(Round-trip)은 최대 5초를 넘지 않아야 한다. (초과 시 처리 지연 UX 스피너 동작)
- **확장성**: 사용자 기억 데이터가 기하급수적으로 늘어남에 대비하여 단기 기억은 RDBMS에, 장기/문맥 기억은 Vector DB(Pinecone 등)에 분리 저장 숙고.
- **가용성/안정성**: 프롬프트 인젝션 방어(System Prompt 최우선 고정). 비용 초과 방지를 위한 일일 대화 횟수 제한(Rate Limiting/Energy System).
