# Task 5: 멘탈 헬스 대시보드 및 위기 감지(Safety) 로직 구현

## 📌 목표 (Goal)

다마고치와의 단순한 대화를 넘어, 축적된 사용자 발화 데이터(`logs`)를 분석해 시각화된 [통계(코칭 리포트)]를 제공하고 극심한 우울감(Negative Index) 감지 시 전문가(1393 연동)의 도움을 권장하는 멘탈 케어 안전망을 설치합니다.

## 📝 세부 업무 내용 (Detailed Workflow)

### 5-1. 통계 데이터 분석 및 API 전처리기 작성 (FastAPI)

- `GET /api/v1/report/{user_id}?period=week` (주간/월간 리포트 호출 엔드포인트 마련)
- DB의 `logs` 테이블 조인 후, 이번 주 사용자의 **가장 많이 나타난 감정(Ekman 도메인)**과 발화 점수(공감, 논리, 매력)의 평점(Average)를 계산.
- SQL 집계 함수(Group By) 처리 또는 Pandas Dataframe 사용.

### 5-2. 프론트엔드 - 코칭 대시보드 (Chart.js / Radar Chart) 연결

- React 애플리케이션에 대시보드 라우트를 생성하고, API 결과를 받아 `react-chartjs-2`의 레이더 차트(`<Radar data={data} />`)로 렌더링.
  - 데이터 축 `[공감, 논리, 매력]`
  - 예시: "주인님은 공감능력은 80점이나 논리성이 조금 부족하군요!" 등 GPT 요약 응답 텍스트를 카드 형태로 제시.
- 부가 기능: 워드 클라우드 패키지(`react-wordcloud` 등)를 통해 가장 빈도수가 높은 긍정어/부정어를 시각화.

### 5-3. AI 감정 모니터링 경보 및 위기감지 스케줄러 (Celery / APScheduler)

- (백엔드 관점) 단순 채팅 시점뿐만 아니라, 하루에 1번씩 "최근 3일간의 부정 수치 비율(`sentiment == 'SADNESS' or 'ANGER'`)을 계산.
- 만일 부정 수치가 80%를 넘었거나, 발화 내용 중 특정 금칙어/위험 단어("죽어", "우울해", "끝내고 싶다")가 발견되면 `damagotchis.status` 를 `SOS_MODE` 로 강제 변경.
- **프론트엔드 모달 강제 렌더링 (SOS Trigger)**:
  - 프론트가 주기적 폴링이나 접속 시 상태 조회에서 `status === 'SOS_MODE'` 이면, 다마고치가 우는/걱정하는 이미지로 고정되고, 다음과 같은 모달이 노출됨.
    > "주인님 요즘 많이 힘든 것 같아요... 제가 언제나 곁에 있지만 조금 더 큰 도움이 필요하다면 1393 상담사 선생님께 연락해 보시는 건 어떨까요?" (전화걸기 a 태그 연동)

### 5-4. 성능 부하와 데이터 격리

- 통계 쿼리를 매번 날리면 DB에 부하가 큼. 매일 새벽 3시에 전일자 데이터를 마이그레이션 및 요약해 두는 방식(ETL 배치 설계)을 검토.
